# Host skill discovery

Checked on 2026-10-01. This note describes local, repository-specific skills stored at `~/.stow/skills/<owner>/<repo>/<name>/SKILL.md`. The host must discover a skill before its command menu can show it. An instruction in `AGENTS.md` can guide an agent to read a file, but it does not register a command with a host.

| Host | Documented discovery path | Direct invocation | External overlay route |
| --- | --- | --- | --- |
| Claude Code | Project `.claude/skills/<name>/SKILL.md`, or `<added-dir>/.claude/skills/<name>/SKILL.md` with `--add-dir` or `/add-dir`. Individual skill folders in a project location may be symlinks. [Claude skill locations](https://code.claude.com/docs/en/skills#choose-where-skills-load), [external directories](https://code.claude.com/docs/en/skills#load-skills-from-a-directory-outside-the-project) | `/name`. [Claude skills](https://code.claude.com/docs/en/skills) | Create an external host view whose `.claude/skills/` contains links to overlay skill folders. Start Claude Code with `--add-dir <host-view>`. This preserves the target checkout. |
| Codex CLI and IDE | Scans `.agents/skills` from the current directory to the repository root. It follows symlinked skill folders. [OpenAI local skill locations](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills) | `$name` or `/skills`, rather than `/name`. The model can also choose a skill from its description. [OpenAI skill invocation](https://learn.chatgpt.com/docs/build-skills#how-chatgpt-and-codex-use-skills) | Place per-skill links in the checkout's `.agents/skills/`, then exclude the local entries from Git. This route still writes links into the checkout. |
| Cursor | Project `.agents/skills/` or `.cursor/skills/`; the documented user paths apply across projects. [Cursor skill directories](https://cursor.com/docs/skills#skill-directories) | Search by typing `/` in Agent chat. The model can also choose a relevant skill. [Cursor skill use](https://cursor.com/docs/skills#how-skills-work) | A user-level `workspaceOpen` hook can supply a workspace-specific external plugin path. The plugin must present skills through Cursor's plugin layout. See below. |

Claude Code watches skill directories that existed when it started and applies `SKILL.md` changes in a running session. If a top-level skill directory was created after startup, `/reload-skills` can load it. That new directory needs another `/reload-skills` for later changes. [Claude live skill updates](https://code.claude.com/docs/en/skills#edit-a-skill-during-a-session) Codex also detects skill changes automatically and recommends a restart when an update does not appear. [OpenAI skill creation](https://learn.chatgpt.com/docs/build-skills#create-a-skill) Cursor documents discovery when it starts. [Cursor skill use](https://cursor.com/docs/skills#how-skills-work)

## Cursor external plugin path

Cursor runs `workspaceOpen` when its desktop app or CLI opens a workspace and when the workspace folders change. The hook receives absolute `workspace_roots` and can return absolute `pluginPaths` for the current workspace. A hook in `~/.cursor/hooks.json` applies at user level, so it can resolve each workspace root to an overlay without writing to the checkout. Cursor skips this hook when the window has no workspace folders. [Cursor hook event and schema](https://prod.cursor.com/docs/hooks#workspaceopen), [user-level hook configuration](https://prod.cursor.com/docs/hooks#quickstart)

The path must identify a plugin directory. Cursor accepts a root `plugin.json` for an Agent Plugin or `.cursor-plugin/plugin.json` for a Cursor Plugin. Its default skill location is `skills/<name>/SKILL.md`. A Cursor Plugin manifest can select a different relative skill path. This permits a generated external plugin view that maps the selected overlay to Cursor's plugin layout. [Cursor plugin formats](https://prod.cursor.com/docs/reference/plugins#supported-plugin-formats), [plugin discovery](https://prod.cursor.com/docs/reference/plugins#component-discovery)

**Requires a smoke test:** The official plugin reference illustrates a relative manifest path such as `"skills": "./my-skills/"`. Test `"skills": "./"` against a plugin whose skill folders sit beside the manifest. Test a plugin with symlinked skill folders through `workspaceOpen` as a separate case. A generated plugin view with copied skill folders follows the documented default `skills/<name>/SKILL.md` shape. For comparison, Cursor skips a local plugin import symlink when its target is outside `~/.cursor/plugins/local`. That rule concerns the plugin directory link at the local import path. [Cursor plugin discovery](https://prod.cursor.com/docs/reference/plugins#component-discovery), [Cursor local plugin imports](https://prod.cursor.com/docs/plugins#test-plugins-locally)

The `workspaceOpen` hook is an IDE lifecycle hook. Cursor lists it as unavailable in Cloud Agents, and user-level hooks stay on the local machine. This path therefore serves local Cursor desktop and CLI workspaces. [Cursor cloud hook support](https://prod.cursor.com/docs/hooks#hooks-not-available-in-cloud-agents)

For portable metadata, use a `SKILL.md` with `name` and `description`. Cursor requires lowercase letters, digits, and hyphens in the name, and the name must match the containing folder. Codex uses the description for automatic selection. `stow add` and `stow adopt` validate these fields before exposing a skill. [Cursor skill format](https://cursor.com/docs/skills#skillmd-file-format), [OpenAI skill format](https://learn.chatgpt.com/docs/build-skills#build-skills)

Claude Code cloud sessions use account skills or committed project skills. Cursor keeps project skills and local `~/.agents/skills/` outside its Cloud Agent sync path. [Claude cloud sessions](https://code.claude.com/docs/en/skills#use-skills-in-cowork-and-cloud-sessions), [Cursor cloud skills](https://cursor.com/docs/skills#skill-directories)

## Ways to connect a workspace

The overlay identifies a repository by its `origin` URL. Host discovery must also know which checkout is active. A user-level skills directory serves every checkout, so it cannot give the host a different repository-specific skill list for two open projects by itself. This is an inference from the documented user and project discovery scopes above.

| Mechanism | What it can do | Limit |
| --- | --- | --- |
| Host workspace API | Cursor's user `workspaceOpen` hook receives workspace roots and returns plugin paths. Claude Code accepts an external directory at launch. These select the overlay for one workspace without checkout files. [Cursor hook](https://prod.cursor.com/docs/hooks#workspaceopen), [Claude external directories](https://code.claude.com/docs/en/skills#load-skills-from-a-directory-outside-the-project) | Cursor needs a valid plugin view. Claude Code needs a launch argument or an in-session `/add-dir`. |
| Local skill links | Codex follows linked skill folders under `.agents/skills/`. A link can point to the canonical overlay. [OpenAI skill locations](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills) | The link is visible inside the checkout. Verify Cursor link handling before using the same path there. |
| Git local exclusion | `$GIT_COMMON_DIR/info/exclude` holds per-repository ignore patterns outside tracked files. Use exact link paths, and check for tracked collisions before creating links. [Git ignore rules](https://git-scm.com/docs/gitignore) | An ignore rule affects untracked paths; it does not protect an already tracked file or stop an explicit forced add. Git worktrees share the common Git directory. [Git worktrees](https://git-scm.com/docs/git-worktree) |
| Shell entry point | A wrapper can reconcile links before launching a CLI. A zsh `chpwd` hook can run when a shell changes directory. [zsh hooks](https://zsh.sourceforge.io/Doc/Release/Functions.html) | This path covers shell activity. An editor opened through its GUI has a separate entry point. |
| File event daemon | macOS FSEvents can notify a process when watched directory trees change. [Apple FSEvents](https://developer.apple.com/documentation/coreservices/file_system_events) | It still needs a checkout registry and host-specific discovery output. It adds a resident process to a small CLI. |
| Virtual filesystem or mount | It can present overlay files at another filesystem path. This is an architectural inference. | The host must still scan that path. A mount does not add a native skill discovery rule or a slash command. |
| MCP prompts | A server can list user-selected prompt templates, which some clients display as commands. [MCP prompts](https://modelcontextprotocol.io/specification/draft/server/index) | A prompt is a different host primitive from a discovered `SKILL.md`. The server still needs the active workspace identity, and command naming depends on the client. |

The implemented route uses one canonical overlay and project skill links. The `agents` setting in `~/.stow/config.json` selects the host paths. `stow add` copies an external skill, while `stow adopt` moves a generated checkout skill to the overlay and leaves a link. `stow sync`, or `stow` without arguments, reconciles the current checkout. Claude Code receives links in `.claude/skills`; Codex and Cursor receive links in `.agents/skills`. Exact Git local exclusions keep these links out of normal Git additions. The external Claude view and Cursor plugin hook described above remain alternatives for a future adapter.

An `origin` URL is a convenient naming key, not proof that a checkout should load private instructions. A checkout can change its own remote configuration. A first `stow add` in that checkout can record local trust; a new clone with the same `origin` should then require a deliberate trust decision before an automatic host adapter exposes private skills. This is a proposed safeguard inferred from the repository-controlled identity.
